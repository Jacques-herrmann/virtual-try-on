# Plan d'implémentation — Sous-projet 3 : Vinted

Spec : `docs/superpowers/specs/2026-10-10-vinted-design.md` (référencée ci-dessous par « spec §x »).
Branche : `feat/vinted` (créée depuis `feat/app` ; à rebaser sur `main` une fois la PR de l'app mergée).

## Conventions

- **TDD** pour le cœur, `vto.vinted` et l'API : écrire le test → le voir échouer → implémenter → `pytest` + `ruff check` verts → commit.
- Front : Vitest pour la logique (stores, galerie) ; vues vérifiées à la main dans `vto-app --dev` + `npm run dev`.
- **Un commit par tâche**, message court en anglais à l'impératif minuscule (`add vinted data schema`).
- Tests Python : fixture `data_dir`, `FakeClient`, aucun appel réseau (`httpx.MockTransport`), aucun `sleep` réel (pauses et délais injectables). Tests Playwright marqués `browser`.
- Les routes de la spec §6 sont servies sous le préfixe `/api` comme les autres (`/api/vinted/status`…).
- Textes visibles par le client : français, sans jargon, même ton que l'app.
- Cocher les cases au fur et à mesure.
